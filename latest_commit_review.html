⚙️ 4 大核心改動技術剖析
1. BVH 射線判定（防止內層破面）
【問題】 舊演算法只要法線朝向大致向前就一律外推，連衣服或夾層背後的內面也被做成甲片，動作一跑就會破面。
【解法】 建立 BVHTree，從物體外側往內打射線（Raycast）。只有直接暴露在外層、沒有被遮擋的三角形才會生成厚度外殼。
2. 外推高度上限與邊界抑制（max_lift）
【問題】 弧度大的曲面上，外推會過度膨脹，讓原本俐落的輕甲看起來像浮空的塑膠殼。
【解法】 引入 fit_profile，設定 max_lift = 0.042 與 flatten = 0.30，壓制高弧度區的暴衝高度，維持機械稜角感。
3. 精確頂點 UV 配對（保證法線與頂點色）
【問題】 舊版透過鄰近三角形重心內插計算法線與顏色，容易造成縫合處光影黑斑或貼圖顏色滲漏。
【解法】 建立 (point, uv) 座標精確雜湊表。若能在原始模型找到完全一致的點與 UV，直接複製原始法線與顏色，零誤差還原。
4. 編譯前置指紋校驗（防過期與靜默失效）
【問題】 改了 Python 幾何演算法，但開發者忘了跑 Blender 重產 JSON 就直接編譯 Godot 場景，導致產出物不同步。
【解法】 build_meshes.py 計算來源程式碼的 SHA-256 並寫入 build_state.json。compile.gd 只要發現指紋不符直接中斷編譯報錯。

⚠️ 為什麼 angular_armor_test 目前會報錯？

因為本 commit 的目的是「轉移開發中的演算法進度」。測試腳本 angular_armor_test.gd 預設預期 32 套裝甲必須全部生成完成，且商店預覽寫死了檢查第 21 與 28 套。但目前硬碟中僅烘焙了 00 與 09 兩套。

解法： 修改測試腳本，改為「只驗證目前已存在的套裝」（或傳入 --ids=0,9），這樣在推進新模型烘焙的過渡期內，測試就能立即轉為綠燈 PASS，同時持續守護已完成的套裝！
